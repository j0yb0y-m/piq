# piq v2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn piq into a production-usable security-first AUR helper: trustworthy verdicts, a real source-scanning and sandboxed build pipeline, a safe install path, and a scriptable CLI.

**Architecture:** Commands parse flags and render; `internal/pipeline` orchestrates clone → scan → fetch → source scan → build → inspect → confirm → `pacman -U`. Scanner rules are calibrated against a benign and a malicious corpus, and scoring applies config filters before gates and thresholds.

**Tech Stack:** Go 1.27, Cobra, Lip Gloss v1, `mvdan.cc/sh/v3`, `go-git`, `klauspost/compress/zstd`, `go-srcinfo`, bubblewrap, makepkg, pacman, vercmp.

**Spec:** `docs/superpowers/specs/2026-11-10-piq-v2-design.md`

## Global Constraints

- Go 1.27.0; module `github.com/j0yb0y-m/piq`; Linux/Arch only.
- New dependency allowed: `github.com/charmbracelet/lipgloss` at v1. Do not add a TUI, solver, or JSON-schema library.
- All user-facing output goes through `internal/ui`. After Task 1, `grep -rn 'fmt\.Print' cmd/piq` must return nothing.
- ANSI is never emitted when stdout is not a terminal, when `NO_COLOR` is set, or in JSON mode.
- Errors are lowercase, wrapped with `%w`, and printed exactly once. Runtime errors do not print usage.
- Unit tests use no network: `httptest` for AUR, temp git repos for history, temp tar.zst for inspect, stub executables on `PATH` for pacman/vercmp.
- `makepkg` never runs as root. `pacman` is elevated only through the configured `sudo_cmd`, split into fields.
- No silent unsandboxed build. Missing bwrap is an error unless the caller explicitly allows it.
- **Commits:** per project rules, do not commit or push unless the user explicitly asks. Commit steps below are pending approval.
- Verification for every task: `gofmt -l .` empty, `go vet ./...` clean, `go test ./...` passing.

## Review Focus

These are the failure modes most likely to hurt a real user. Each is pinned by a test in the task that owns the code.

1. `piq scan --json | jq` must emit pure JSON on stdout with no ANSI and no human text. — Task 10.
2. A missing bwrap or disabled user namespace must fail loudly; piq must never fall back to an unsandboxed build silently. — Task 11.
3. A mainstream package such as `paru` must produce no gate hit, while malicious fixtures still gate. — Tasks 7 and 8.
4. An aborted or failed install must not write a review record or claim success. — Task 15.
5. `sudo_cmd = "sudo -A"` or `"doas"` must work as separate argv fields, and cache paths containing spaces must survive. — Task 13.
